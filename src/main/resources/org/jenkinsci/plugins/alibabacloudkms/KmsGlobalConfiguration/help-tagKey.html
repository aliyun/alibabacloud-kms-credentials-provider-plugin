KMS matches this value as a case-sensitive substring of each secret's tag keys, not as an exact key, so a secret is selected when any of its tag keys contains this text. Keep it long enough to be specific: jenkins also picks up a secret tagged owner:jenkins-ci. Defaults to jenkins:credentials. Can also be set with the ALIBABA_CLOUD_KMS_TAG_KEY environment variable or the jenkins.alibabacloud-kms.tagKey system property, which take precedence over this field — a value typed here has no effect while either is set.

Every other tag this plugin reads is prefixed with jenkins:credentials:, so that tags of your own on the same secret are never mistaken for configuration:

  • jenkins:credentials:type — the credential kind: string (default), secretFile, username, sshUserPrivateKey or certificate. This is the only tag that selects the kind; the others just supply values to it.
  • jenkins:credentials:id — the Jenkins credential id. Falls back to the KMS secret name when the tag is missing or blank.
  • jenkins:credentials:scope — GLOBAL (default) or SYSTEM. Use GLOBAL for anything a job consumes: a SYSTEM credential is visible only in the Jenkins root context, so withCredentials inside a job cannot find it.
  • jenkins:credentials:username — the account name for username and sshUserPrivateKey credentials.
  • jenkins:credentials:filename — the file name for secretFile credentials. Defaults to <secret name>.txt.
  • jenkins:credentials:passphrase-id — another secret holding the SSH key passphrase.
  • jenkins:credentials:password-id — another secret holding the certificate password.
  • jenkins:credentials:auto-parse-secret — set to true to split a managed secret's value into an account name and password. See below.

Credentials are imported with an empty Jenkins description, so listing never reads individual secret descriptions from KMS.

Credential discovery has a fixed 30-second window. A lookup after it reloads membership, tags, and pending deletion state in the background and returns the previous list meanwhile, so only the very first lookup for a given configuration waits on KMS; a controller that stops looking credentials up drops the entry after five minutes. A reload that fails keeps the previous list rather than replacing it with an empty one — secret values are still read live, so a secret deleted during a KMS outage fails where it is used instead of disappearing from every picker. Click Reload cache to force a reload immediately. A secret scheduled for deletion is not listed at all.

Unchanged credential objects and their value suppliers separately use the configured Cache time (seconds); this does not alter the 30-second discovery window.

Managed secrets

For a managed secret the value is a JSON object rather than a bare string. It is split into the account name and password only when both jenkins:credentials:type=username and jenkins:credentials:auto-parse-secret=true are set. The fields read are:

  • Rds, Redis, PolarDB — AccountName/AccountPassword
  • ECS — UserName/Password
  • RAMCredentials — AccessKeyId/AccessKeySecret

GetSecretValue returns every managed type as a flat object. The {"Accounts":[{"AccountName":...,"AccountPassword":...}]} shape you may have seen is only the CreateSecret input for an RDS secret; KMS never hands it back, so it is not read here.

Without the tag, or with any value other than true, the whole value stays the password — the behaviour from before splitting existed. A jenkins:credentials:username tag, when present, always wins over the account name inside the secret, which also means a picker is rendered without reading the secret's value.

Every other type, Generic included, keeps its whole value as the password whatever jenkins:credentials:auto-parse-secret says, because there is no known field layout to read an account name from.

Once split, the pair is cached together for Cache time (seconds). When it expires, the next read reloads both halves together: rotation can replace the account name as well as the password, and half of an old pair combined with half of a new one authenticates as nothing at all. A read that fails is remembered for 30 seconds instead — even at a 0 cache time — so an outage costs one timeout per secret rather than one per credential picker entry. Reload cache makes later lookups create a fresh credential object.

Note the withAlibabaCloudKms pipeline step is not gated by jenkins:credentials:auto-parse-secret, because it reads the secret by name and never sees its tags. For a managed secret it always binds the declared variable to the whole value, and additionally binds <VAR>_USERNAME and <VAR>_PASSWORD.
